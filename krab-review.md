# krab: заметки по ревью (ветка `CLI`)

Что проверялось: `krab-core` (ядро) и `krab-cli` (новый CLI) на ветке `CLI`, коммит `a4ee1f5`.

**Важно:** собрать проект и прогнать тесты не удалось, из окружения ревью нет доступа к `index.crates.io`. Всё ниже получено чтением кода. Пункт 1 нужно подтвердить обычным `cargo check` на Linux или macOS.

## Критично

### 1. `File` не импортирован в `krab-core/src/storage.rs`

В начале файла:

```rust
use std::fs::{self, OpenOptions};
```

А в `write_atomic` под `#[cfg(unix)]` вызывается:

```rust
if let Ok(d) = File::open(dir) {
    let _ = d.sync_all();
}
```

Тип `File` нигде не импортирован, поэтому на Unix-системах это не должно компилироваться. На Windows блок вырезается через `cfg`, и ошибка не видна.

**Как исправить:** добавить `File` в импорт:

```rust
use std::fs::{self, File, OpenOptions};
```

Либо написать `fs::File::open(dir)`.

**Как проверить:** `cargo check --workspace` на Linux/macOS (или через WSL). Лучший способ не ловить такое руками: CI на Linux (см. пункт 10).

## Важно

### 2. Повторяющийся код в `krab-cli/src/main.rs`

Блок «спросить мастер-пароль, открыть хранилище, при ошибке выйти» скопирован в `List` и `Add` один в один. Вся логика лежит в одной функции `main`, она будет только разрастаться.

**Как исправить:**
- вынести функции `prompt_password(msg) -> String` и `open_vault(path) -> Vault`;
- каждую команду сделать отдельной функцией (`cmd_init`, `cmd_list`, `cmd_add`), а `main` оставить диспетчером;
- завести один `fn fail(msg) -> !` вместо россыпи `eprintln!` + `process::exit(1)`.

### 3. `Add` молча сохраняет неполную запись при Ctrl+C

Результаты запросов игнорируются:

```rust
if let Ok(url) = Text::new("URL/Сайт (опционально):").prompt() { ... }
```

Если пользователь нажал Ctrl+C или Esc посреди ввода, `Err` просто проглатывается, и запись всё равно добавляется и сохраняется. Для опциональных полей такое поведение неверно: отмена ввода должна отменять всю операцию.

**Как исправить:** обрабатывать `Err` из `inquire` (особенно `OperationCanceled` и `OperationInterrupted`) как отмену: выйти без сохранения. Для действительно опциональных полей использовать `.prompt_skippable()`, который различает «пропустил» и «отменил».

### 4. Не хватает базовых команд

Сейчас есть только `init`, `list`, `add`. Прочитать сохранённый пароль нельзя вообще.

**Нужно добавить (минимум):**
- `get` / `show`: показать запись (секретные поля по запросу или по флагу);
- `remove`: удалить запись с подтверждением (решение из `ARCHITECTURE.md`: удаление окончательное, подтверждение обязано делать интерфейс);
- `edit`;
- поиск (в ядре по плану он должен смотреть и в `source`);
- смена пароля / перенастройка KDF (в ядре `Vault::rekey` уже есть).

Для `get` / `remove` нужен способ указать запись: по id (сейчас `list` печатает UUID целиком, неудобно) или по префиксу id / названию.

## Средне

### 5. Эмодзи используются как ключи для `match`

```rust
let options = vec!["🔑 Login", "📝 Note", ...];
...
match choice {
    "🔑 Login" => EntryType::Login,
    ...
    _ => EntryType::Other,
}
```

Строки одновременно показываются пользователю и сравниваются. Опечатка или смена текста в одном месте незаметно уведёт ветку в `_ => Other`.

**Как исправить:** завести маленький enum (или массив пар `(EntryType, &str)`) с `Display`, передавать его в `Select` и сразу получать `EntryType` без сравнения строк.

### 6. Неиспользуемые зависимости

В `krab-cli/Cargo.toml` подключены `indicatif`, `comfy-table`, `rpassword`, но в `main.rs` они не используются (пароли запрашиваются через `inquire`).

**Что сделать:** либо использовать по назначению (`indicatif` для спиннера во время калибровки Argon2 вместо «это займёт около секунды»; `comfy-table` для вывода `list`), либо убрать. `cargo machete` или `cargo udeps` покажет точно.

### 7. Подтверждение пароля в `init` сделано вручную

Используется `.without_confirmation()` дважды плюс ручное сравнение. У `inquire::Password` есть встроенное подтверждение (по умолчанию включено), оно проще и даёт нормальное сообщение об ошибке. Заодно стоит решить, нужна ли минимальная длина мастер-пароля (сейчас проверяется только непустота).

### 8. Хрупкий `Vault::create` и `path.exists()`

В `Vault::create` проверка `path.exists()` и дальнейшая запись через временный файл + `rename` не атомарны вместе: между проверкой и переименованием файл может появиться, и `rename` его перезапишет. Для личного CLI риск минимальный, но стоит знать. Если захочется строгости: для самого первого создания использовать `hard_link` / `OpenOptions::create_new` для итогового файла.

## Мелочи и косметика

### 9. ASCII-краб

Константа `ASCII_CRAB` в `main.rs` выглядит поломанной: в строке `/\_/\  /\_/   ( o.o )( o.o )` несколько фрагментов слиплись. Это первое, что видит пользователь при `init`. Поправить рисунок или временно убрать.

### 10. Нет CI

Ни `cargo fmt --check`, ни `clippy`, ни тестов в автоматике. Пункт 1 был бы пойман сразу.

**Предложение:** GitHub Actions с матрицей `ubuntu-latest` + `windows-latest` и шагами `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`, `cargo test --workspace`.

### 11. Нет тестов у `krab-cli`

В ядре тесты хорошие (граничные значения KDF, подмена AAD, обрезанный файл, права файла). У CLI тестов нет. Для проверки через `assert_cmd` интерактивные запросы нужно сделать подменяемыми или добавить неинтерактивный режим (пароль из переменной окружения или из stdin).

### 12. Редакция и версии

- `krab-cli` на `edition = "2024"`: убедись, что у `krab-core` та же, и укажи `rust-version` в `Cargo.toml`, чтобы пользователи получали понятную ошибку на старом компиляторе.
- В `krab-cli/Cargo.toml` зависимость от ядра задана как `version = "0.1.0", path = "../krab-core"`. Для приватного воркспейса достаточно `path`; `version` нужна, только если планируешь публиковать на crates.io.

### 13. `ARCHITECTURE.md` отстаёт от кода

- Статус в шапке: «код не написан, Rust в окружении ещё не ставили». Это уже неправда.
- В разделе 2 и 11 `krab-cli` значится как «пока не создана» / шаг 4 плана.
- В дереве проекта (раздел 3) нет `krab-cli/`, а сам файл лежит в `krab-core/docs/`, хотя в дереве указан в корне.
- Раздел 10: «Публичное API `krab-core` проектируем следующим шагом». В `lib.rs` оно помечено как черновое, стоит обновить и там, и здесь.

## Что в проекте сделано хорошо (чтобы не сломать при правках)

- Заголовок целиком идёт в AAD, nonce новый при каждом сохранении.
- Границы параметров Argon2id проверяются до выделения памяти (и в `Header::parse`, и повторно в `derive_key`).
- Атомарная запись, права `0600`, уборка временного файла при ошибке.
- `Zeroizing` / `ZeroizeOnDrop` для ключа и записей, `Debug` не печатает секреты.
- `Vault::rekey` откатывает состояние в памяти, если запись на диск не удалась.
- Неизвестные типы записей и полей сохраняются «как были» (`open_enum!`).
